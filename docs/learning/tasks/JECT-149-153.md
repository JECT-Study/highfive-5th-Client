## 선택과 실제 연결

목표는 생성 화면과 수정 화면을 각각 보여주는 데모가 아니라,
사용자가 방금 만든 공연 ID의 상세를 열고 같은 공연을 수정하는 흐름이다.

- 생성은 JECT-149의 실제 `ConcertCreationView`와 ViewModel을 사용한다.
- 수정은 JECT-153의 실제 `ConcertEditView`와 ViewModel을 사용한다.
- `OfflineConcertRepository`는 비어 있는 ID별 저장소다. 생성 입력을 보관하고
  다른 ID를 발급하며, 수정 화면을 열 때 해당 ID의 현재 전체 스냅샷을 읽는다.
- ID별 수정 Repository가 저장하면 그 레코드의 버전만 증가한다.
  상세로 돌아왔을 때 해당 ID를 다시 읽고, 홈 목록도 변경 제목을 읽는다.
  오래된 버전은 충돌로 거절한다. 다른 공연을 덮어쓰지 않는다.
- 밴드 A/B와 대표자 역할은 명시적인 오프라인 QA 예시다.
  이 ID·권한·초기 버전은 운영 데이터나 POST 응답으로 가장하지 않는다.
- `main_preview.dart`는 dev/debug 전용 별도 시작점이다.
  SDK 초기화·setupDi·secure storage·실제 세션·Dio를 만들지 않는다.
  앱 종료 시 메모리 데이터는 사라진다.

주요 파일:

1. `apps/mobile/lib/main_preview.dart`: 실행 경계.
2. `apps/mobile/lib/app/offline_preview_app.dart`: 홈 → 생성 결과 ID → 상세 → 수정 → 상세.
3. `apps/mobile/lib/features/performances/data/repositories/offline_concert_repository.dart`:
   생성·조회·ID별 저장·버전 충돌.
4. `apps/mobile/lib/features/performances/presentation/views/concert_creation_view.dart`와
   `concert_edit_view.dart`: 실제 입력·명령·성공 후 이동.
5. `apps/mobile/lib/app/router.dart`: 정상 인증 경계와 기존 라이브 폼 연결.

## 확인한 API 계약과 운영 차단

2026-11-26 `GET https://dev-api.highfive-app.link/v3/api-docs`를 직접 읽어
HTTP 200을 확인했다. GET 문서 조회 외의 서버 요청을 보내지 않았다.

| 확인한 항목 | 실제 계약과 영향 |
| --- | --- |
| `/api/v1/concerts` | POST만 있다. 응답 `ConcertCreateResponse`에는 `concertId`만 있다. |
| `/api/v1/concerts/{concertId}` | PUT만 있다. 공연 상세 GET은 노출되어 있지 않다. |
| `ConcertUpdateRequest.version` | 필수다. 생성 응답으로 version을 추론할 수 없다. |
| 전체 교체 PUT | title, genres, recruitTeamCount, 날짜·시간·장소·주소·지역·금액·포스터·version을 보존해야 한다. |
| `MyInfoResponse.hasBand` | ACTIVE 밴드 소속 여부뿐이다. 밴드 ID나 대표자 역할이 아니다. |
| 밴드 경로 | Swagger에 `/bands` 조회 경로가 없다. |
| 대표자·참여 권한 | POST는 대표자 확인 미구현, PUT은 참여 팀 멤버 확인 미구현이라고 설명한다. |
| 모집 공고 | `/concerts/{concertId}/recruit-posts` POST는 별도 명령이다. 공연 생성 성공과 동일하게 취급하지 않는다. |

따라서 정상 앱의 홈에 가짜 밴드 선택과 자동 편집 연결을 붙이지 않았다.
생성 폼은 호출자가 확보한 `HostBand`, 수정 폼은 전체 값·권한·재조회 함수를
담은 `ConcertEditContext` 없이는 열리지 않는다. ID 쿼리만으로 쓰기 폼을 만들지 않는다.
운영 연결에는 인증된 주최 밴드 ID·역할 조회, 같은 공연의 최신 전체 상세·version·
현재 참여 권한 조회 계약이 필요하다. 이 공백은 오프라인 QA 성공으로 해결되지 않는다.

## 최종 실행 결과와 사용자 QA 인계

사용자가 기기·시뮬레이터·화면 QA를 직접 하겠다고 명시한 뒤에는
기기 설치·실행·스크린샷·브라우저 QA를 더 실행하지 않았다.
그 시점에 이전 기기 명령은 모두 종료된 상태였다.
아래 기기 실행은 그 지시 이전의 이력이며 사용자 수동 QA 완료를 뜻하지 않는다.

| 검사 | 실제 결과 |
| --- | --- |
| `fvm flutter pub get` | 성공. SDK `integration_test`를 dev dependency로 추가했고 SDK·운영 의존성 버전은 바꾸지 않았다. |
| `fvm flutter test --reporter expanded` | 최종 전체 호스트 테스트 382개 통과, 종료 0 |
| `fvm dart analyze --fatal-infos` | No issues found, 종료 0 |
| `fvm flutter analyze --no-pub` | 한글 경로 문제를 피한 동일 소스 `/tmp/highfive-concert-flow.wpa6bF`에서 `No issues found! (ran in 3.1s)`, 종료 0 |
| `fvm dart format --set-exit-if-changed --output=none lib test tool integration_test` | 255개 파일 변경 없음, 종료 0 |
| `fvm dart run tool/check_imports.dart` | 161개 파일 import 방향 OK, 종료 0 |
| `fvm dart run build_runner build --delete-conflicting-outputs` | 성공, 12 outputs. 이전/이후 생성 파일 7개의 SHA-256 모두 동일. 현재 build_runner가 삭제 옵션을 무시한다는 경고는 그대로 기록한다. |
| `git diff --check` | 공백 오류 없음 |
| iPhone simulator dev/debug 빌드 | 이전 실행에서 성공. 마지막 통합 테스트 Xcode 빌드 29.7초 |
| `fvm flutter test integration_test/concert_flow_test.dart --flavor dev -d 0E7CC0BE-3FE0-4124-9D2D-825E14BBB18D --reporter expanded` | 지시 이전 1개 통과, `00:13 +1: All tests passed!`, 종료 0 |

기기 테스트는 실제 `main_preview.main()`을 실행하고
`Concert Alpha` 생성 → 상세 → 제목 `Concert Alpha Updated` 저장 → 상세 반영 →
`Concert Beta` 생성 → 두 ID의 다른 제목 보존 → 첫 ID 수정 재진입의 최신 값을 검증했다.
이는 iPhone에서 실행한 Flutter integration test이며, 네이티브 키보드 입력의
모든 조합을 수동 검증했다는 뜻은 아니다.

**테스트 종료 정리 동작 사고:** `flutter test`의 기기 실행은 고정 SDK
`flutter_tools/lib/src/commands/test.dart:309`에서 `uninstall` 기본값이 true다.
이를 사전에 확인하지 못해 첫 실행 종료 시 dev 앱과 캡처가 있는 앱 컨테이너가
제거됐다. `integration_test_device.dart:149`의 `uninstallApp` 분기를 확인했다.
실제 서버 쓰기나 인증 저장소 API 호출은 없었지만 컨테이너 보존은 실패했다.
기기 테스트가 만든 PNG 경로 로그는 있었으나 종료 뒤 파일이 없어 호스트 회수가 실패했다.
최종 기기 캡처를 보관했다고 주장하지 않는다.

이 문제를 알린 뒤 사용자가 기기 QA를 직접 맡겼다. 따라서 재설치나 추가 기기
검증으로 만회하려 하지 않고 기기를 그대로 두었다. 이후 사용자가 직접 기기
테스트를 실행한다면 자동 제거 방지 플래그를 반드시 붙인다:

```sh
fvm flutter test integration_test/concert_flow_test.dart \
  --flavor dev -d 0E7CC0BE-3FE0-4124-9D2D-825E14BBB18D \
  --no-uninstall --reporter expanded
```

이 명령은 안내만 남겼으며 이 세션에서 실행하지 않았다.
실제 QA 앱 재설치·실행 여부도 사용자 판단으로 남긴다.

남은 수동 확인:

- 위 직접 검증 1~6 순서의 생성·수정·복귀·다중 ID 분리.
- Component V3와 최종 화면 비교, JECT-258 scoped theme 연결과 Material 팝업 교체.
- 기존 날짜·시간 컨트롤의 선택/취소, 미정 복원, 키보드·작은 화면·접근성.
- 최종 정상 앱과 오프라인 앱을 혼동하지 않는 표시.

호스트 위젯 렌더 PNG는 `apps/mobile/build/concert-flow-qa/`의
`home-empty`, `creation`, `created-detail`, `edit-title`, `saved-detail`,
`home-two-concerts`에 있다. `iphone-creation`·`iphone-created-detail`은
임시 테마 제거 전 수동 조작의 중간 기록이므로 최종 V3 증거로 사용하지 않는다.
원본 두 워크트리는 보존했고 커밋·푸시·PR은 없다.
