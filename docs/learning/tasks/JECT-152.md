# JECT-152 공연 정보와 참여 밴드 프로필

## 범위와 선택

- 사용자가 구현·테스트·골든·읽기 전용 Codex 리뷰·한글 로컬 커밋을 요청했다. 푸시·PR은 하지 않는다.
- JECT-150의 실제 정보 탭·참여자 조회를 확장한다. 별도 roster, 밴드 소유자 기능, 셋리스트, 편집·삭제 명령은 만들지 않는다.
- 날짜·시간·장소는 기존 `ConcertInfoTab`과 `shared/utils/date_format.dart`를 재사용한다.
- 공연 상세가 주는 주소·대관비를 더한다. 대관비를 팀별 청구액으로 나누거나 지도 이미지를 만들어 내지 않는다.
- `recruitment`가 있을 때만 `ShowProgressCard`로 모집 요약을 보인다. 연결되지 않은 공고 작성·공유·문의 버튼은 넣지 않는다.
- 모집 마감은 상대적인 남은 일수 대신 마감 날짜 자체를 보인다. 자정·복귀 시각에 따른 오래된 안내를 피한다.
- 참여 팀 수는 현재 roster와 모집 목표로 계산한다. 주최 팀은 모집 잔여 자리에서 제외한다.
- 공고·공연이 실제 모집 중일 때만 모집 안내를 보인다. 마감·판매 단계의 빈자리는 모집 중으로 표시하지 않는다.
  빈자리 아바타는 최대 5개로 제한하고 요약 수는 정확히 유지한다.
- 프로필의 `ProfileNotice`는 현재 한 화면만 쓰므로 private 위젯이다. 갤러리나 새 global 컴포넌트를 추가하지 않는다.

## 실제 코드 흐름

`routerProvider` → `concertShowRoute()` → `ConcertDetailView`
→ `ConcertInfoTab` → `ConcertParticipantsPreview.onBandTap`
→ `/shows/:showId/bands/:bandId` → `ConcertBandProfileView`.

`concertBandProfileProvider`는 `concertDetailProvider`와 `concertParticipantsProvider`의
상태를 조합한다. 별도 프로필 네트워크 요청이나 두 번째 목록 저장소는 없다.
새 파생 provider의 `dependencies`만 선언하며, canonical provider의 세션 scope 수정은 JECT-151 소유다.
확정된 접근 거부·삭제 오류는 다른 조회의 일시 오류보다 우선한다.
수동 재시도는 두 canonical 조회의 완료를 각각 추적해 한 조회가 먼저 실패해도 남은 요청을 중복 실행하지 않는다.
실패한 조회만 새로 시작하고, 이미 진행 중인 조회와 성공한 캐시는 유지한다. 확정된 접근 오류의 복귀는 다른 조회를 기다리지 않는다.
Riverpod 3.4.3은 자동 재시도 타이머 대기와 실제 자동 요청 중에도 `retrying`을 유지한다.
따라서 자동 체인 중에는 수동 버튼을 busy로 두고, 체인이 끝난 뒤에만 수동 재시도를 허용한다.

DTO는 라인업 조회 초안의 `teams[].band.profileImageUrl`, `genres`, `memberCount`를 그대로 읽는다.
JSON에는 세 키가 필요하고 사진 값만 null일 수 있다. 장르·인원 누락·null, 소수 인원은 거부한다.
기존 최소 `ConcertParticipant` 생성자는 호환되며 인원이 없을 때는 null이다. 0명으로 채우지 않는다.

## 표시 상태

| 조건 | 화면 | 다음 행동 |
| --- | --- | --- |
| 조회 대기 | 진행 표시, 이전 프로필 숨김 | 응답 대기 |
| 밴드가 현재 roster에 있음 | 이름·사진·알려진 장르·알려진 인원·함께하는 공연 | X로 닫기 |
| 잘못된 ID 또는 roster에 없음 | 없는 밴드 안내 | X로 닫기 |
| `403/AUTH_005`, `404/CONCERT_001` | 이전 데이터 없이 접근/없음 안내 | 이전 화면으로 |
| 그 밖의 조회 실패 | 실패 안내 | 실패한 조회 재시도, 진행 중인 조회 유지 |
| 조회 후 밴드가 빠짐/권한이 바뀜 | 이전 프로필 숨김 | 없음/실패 안내 |

직접 연 프로필은 닫기·시스템 뒤로 가기에서 공연 정보로 간다.
공연 ID도 잘못됐다면 홈으로 간다.

## 확인된 한계와 직접 확인

- 상세·라인업 GET은 제공된 Swagger에 없어 JECT-148/150의 DI fake를 그대로 사용한다.
- 밴드 프로필 API는 명세에 없다. 소개·미디어·팀원 목록·SNS·지역·연주 경력은 만들지 않는다.
- 장르 이름은 JECT-150의 코드 목록 예시 표를 feature-local formatter로 옮겨 두 화면에서 함께 쓴다.
  코드 목록 API 연동은 별도다. 모르는 코드는 숨긴다.
- Figma의 dark pilot 색을 복사하지 않고 기존 shared 디자인 시스템을 쓴다.
- 사용자 이해와 실서버·사용자 직접 UI 확인은 미확인이다.
- 직접 확인: 공연 정보에서 주소·대관비·읽기 전용 모집 현황 확인 → 밴드 탭 → 프로필 값 확인
  → X로 같은 공연 복귀. 공고 버튼·셋리스트·밴드 관리 버튼은 없어야 한다.
- 문제 발생 시 라우트 등록 → canonical 두 조회의 상태 → DTO 필수 키/정수 파싱 → DI 구현 순서로 확인한다.
